# Thesis workspace — SpaNCy-Shift

Planning material for the thesis. Nothing here is thesis text yet; it decides **what** goes in,
**where**, and **with which evidence and references**.

| File | What it is | Read when |
|---|---|---|
| `00_scope_decisions.md` | The critical part: one research question, what is IN / APPENDIX / OUT and why, red flags to fix | First. Before writing anything |
| `01_outline.md` | Chapter-by-chapter template: purpose, contents, figures/tables, references per section, length | When writing each chapter |
| `02_claims_evidence.md` | Every claim the thesis may make → number → source notebook → status | Before writing any number into the text |
| `03_reference_map.md` | Which reference supports what, in which chapter, verification status | When citing |
| `references.bib` | Starter BibTeX for Overleaf (fields marked `VERIFY` must be checked) | When setting up Overleaf |

## Working rules

1. **One question, one storyline.** Every chapter must serve the research question in
   `00_scope_decisions.md`. If a result does not support a conclusion or justify a design choice,
   it does not go in the main text.
2. **No number without a row in `02_claims_evidence.md`.** Learned methods are reported as
   mean ± SD over ≥ 3 seeds; single-run numbers are labelled as such.
3. **Methods describe the final pipeline only.** How we got there goes in one short
   "Design rationale" section (Ch. 3.6), not as a chronological diary.
4. **Adapt structure to the university's thesis guideline** (page limits, mandatory sections,
   abstract language). The outline here is a generic master's-thesis structure.
